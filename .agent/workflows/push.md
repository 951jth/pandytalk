---
description: 사용자가 "푸쉬해줘", "커밋해줘", "push" 또는 `/push` 등의 키워드로 작업을 요청할 때 처리 방법
---

사용자가 작업을 요청하면 다음 단계를 통해 사용자가 직접 실행할 수 있는 명령어를 제안하세요:

1. **상태 점검**: 우선 `git status` 명령을 내부적으로 실행하여 현재 어떤 파일들이 변경되었는지 확인합니다.
2. **네이티브 변경 확인 (CRITICAL)**:
   - 변경된 파일 중에 `android/`, `ios/`, `package.json`, `app.json`, `app.config.js` 등이 포함되어 있는지 확인합니다.
   - 만약 네이티브 변경 사항이 있다면, **"네이티브 코드 변경이 감지되었습니다. 이 변경 사항을 적용하려면 새로운 바이너리 빌드(EAS Build 등) 및 앱 업데이트 배포가 필요합니다."**라는 안내 문구를 명령어 제안 전에 반드시 포함하세요.
3. **변경 요약 및 메시지 작성**:
   - 변경된 파일 목록을 사용자에게 정렬하여 보여줍니다.
   - 변경 사항을 종합하여 **Conventional Commits** 스타일의 한글 커밋 메시지를 작성합니다. (예: `feat: ...`, `fix: ...`)
4. **명령어 제안**: 사용자가 복사하여 실행할 수 있도록 통합 명령어를 마크다운 코드 블록으로 제시합니다.
   - 명령어 형식: `git add . ; git commit -m "커밋 메시지"`
   - PowerShell 환경을 고려하여 `;` 구분자를 사용합니다.

**주의사항**: 사용자의 명시적인 "실행해줘" 또는 "승인" 답변이 있기 전까지는 `run_command`를 통해 `git commit`이나 `git push`를 직접 수행하지 마세요. 반드시 제안된 명령어를 사용자가 먼저 인지하게 합니다.
