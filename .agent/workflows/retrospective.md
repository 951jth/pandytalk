# 📝 회고록 작성 워크플로우 (Retrospective Guide)

프로젝트 내에서 발생한 주요 기능 추가, 버그 수정, 성능 개선 사항을 기록할 때 아래 규칙을 준수하여 작성합니다.

### 1. 파일명 및 위치 규칙
- **저장 위치**: `retrospectives/` 디렉토리
- **파일명 형식**: `[유형]_[주제]_[YYYYMMDD].md`
  - 유형 예: `feature`, `bugfix`, `hotfix`, `refactor`, `debug_resolve`
  - 주제 예: `chat_sync`, `ai_mention`
  - 예시: `debug_resolve_chat_sync_20260328.md`

### 2. 문서 내부 구조 (Markdown Format)

#### (1) 헤더 (H1)
`# 🚀 [유형]: [제목] (YYYY-MM-DD)` 형식으로 작성합니다. 적절한 아이콘을 조합하여 시각적 효과를 극대화합니다.

#### (2) 📌 개요 (H2)
작업의 배경, 발생했던 문제 현상, 작업의 목적을 간단명료하게 한국어로 작성합니다.

#### (3) ✨ 주요 변경 사항 (H2)
가장 핵심적인 수정 내용을 H3 소제목과 함께 상세히 작성합니다. 코드 상의 특정 로직 이름이나 변수명을 언급하여 정밀도를 높입니다.

#### (4) 🛠️ 기술적 의의 (H2)
이번 작업이 프로젝트의 아키텍처, 성능, 유지보수성, 보안 측면에서 어떤 긍정적인 영향을 미치는지 전문가적 시각에서 정리합니다.

#### (5) 푸터 (Footer)
수평선(`---`) 아래에 기록자와 현재 배포 상태를 명시합니다.
```markdown
---
**기록자**: Antigravity (AI Coding Assistant)
**상태**: [배포 버전 또는 최종 반영 상태]
```

### 3. 언어 및 톤
- **언어**: 한국어
- **톤**: 전문적이면서도 가독성 높은 톤앤매너
- **시각 요소**: 적절한 이모지(Emoji)와 마크다운 문법(Callout 등)을 활용하여 정보의 위계를 명확히 합니다.
