# 코드 리뷰 규칙

## 1. 적용 범위와 작업 경계

- 로컬 변경사항과 GitHub PR의 앱·Functions 코드, 설정, 의존성을 리뷰합니다. 루트와 변경 파일에 적용되는 하위 AGENTS.md를 함께 읽습니다.
- 변경 diff와 관련 호출부·데이터 흐름을 확인하고, 각 검토 항목의 문서를 변경 범위에 따라 읽습니다.
- 리뷰에서는 소스 수정·커밋·push·머지·빌드·배포·스토어 제출을 하지 않습니다. GitHub 리뷰 의견 게시와 아래 검증 실행은 포함하며, 수정은 별도 요청으로 처리합니다.
- 참조 문서의 배포·버전 변경 절차는 리뷰에서 실행하지 않고 검토 기준으로만 사용합니다.

## 2. 리뷰 전 검증

- package.json과 CI의 실제 명령을 확인한 뒤, 리뷰 대상 커밋에서 앱 변경은 기본적으로 `yarn lint`와 `yarn typecheck`를 실행합니다. 시간이 오래 걸리는 `yarn test`는 테스트 코드가 직접 변경되었거나 코어 비즈니스 로직이 변경된 경우에만 제한적으로 실행합니다. 한 검사가 실패해도 나머지 검사는 확인합니다. Functions 검증은 해당 문서를 따릅니다.
- 문서만 변경되면 실행 검증을 생략할 수 있습니다. 도구·의존성·권한 등으로 실행할 수 없으면 이유를 기록하고 미검증으로 보고합니다.
- PR CI 조회가 가능하면 그 결과를 우선 참고하되, 최신 PR 커밋에 대한 검사인지 확인합니다. 이전 커밋의 성공 결과를 현재 변경의 검증 근거로 사용하지 않습니다. 로컬 검증 결과나 CI 상태는 불필요한 서식 없이 핵심만 한국어로 간결하게 보고합니다.
- 🚨 **위험 검증:** 네이티브 코드나 의존성이 추가되었음에도 런타임 버전을 올리지 않아, 기존 런타임 대상으로 업데이트(OTA)가 발행될 위험이 있는지 가장 먼저 확인하여 강력히 경고합니다.

## 3. 관련 검토 기준

- 앱 코드 변경: [architecture.md](architecture.md)를 읽고 계층·의존성·책임 분리 기준을 적용합니다.
- Functions 변경 또는 서버 호출 계약 변경: [firebase-functions.md](firebase-functions.md)를 읽습니다.
- 메시지 동기화·캐시·구독·AI 응답 변경: [chat-review.md](chat-review.md)를 읽습니다.
- OTA 업데이트 및 기본 배포 설정 변경: [eas-update.md](eas-update.md)를 읽습니다.
- 네이티브 앱 버전 및 런타임 버전 변경: [release-versioning.md](release-versioning.md)를 읽고 동기화 상태를 점검합니다.
- 프로젝트 회고록 작성 및 수정: [retrospective.md](retrospective.md)를 읽습니다.

## 4. 리뷰 결과 작성

- 한국어로 작성하며 실제 동작 오류·회귀·데이터 손실·보안·호환성 문제와 명시적인 프로젝트 아키텍처 위반을 다룹니다.
- 발견 사항에는 우선순위, 파일·줄, 발생 조건, 영향과 코드 근거를 제시합니다. 동작 결함과 아키텍처 개선 사항은 구분하고 구조 위반의 영향을 과장하지 않습니다.
- 발견된 논리적 결함이나 아키텍처 위반 사항만 명확하고 간결하게 제시합니다. 검증 실패는 머지 전 해결 항목으로 보고합니다.
- 포맷, 린트, 단순 취향에 따른 리팩터링은 지적하지 않고 핵심 로직 리뷰에 집중합니다.
