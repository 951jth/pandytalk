# 코드 리뷰 규칙

## 1. 적용 범위와 작업 경계

- 로컬 변경사항 및 GitHub PR 리뷰에 적용합니다. 루트와 변경 파일에 적용되는 하위 AGENTS.md도 함께 읽습니다.
- 앱 코드뿐 아니라 functions/의 서버 코드·설정·의존성 변경도 리뷰 대상에 포함합니다.
- 변경 diff를 중심으로 호출부·데이터 흐름·설정 등 판단에 필요한 관련 코드를 확인합니다.
- 리뷰 요청에서는 파일 수정·커밋·push·머지·EAS Update·빌드·스토어 제출을 수행하지 않습니다.
- GitHub PR 리뷰 의견 작성은 허용합니다. 수정 요청은 별도 작업으로 처리하고 기존 승인 규칙을 따릅니다.
- 코드 리뷰 요청에는 린트·타입 체크·테스트 실행이 포함됩니다. 별도 실행 요청을 기다리지 않고 아래 사전 검증 규칙을 따릅니다. 빌드·배포는 실행하지 않습니다.

### 리뷰 전 사전 검증

- 먼저 package.json과 CI 워크플로우에서 검증 명령을 확인하고, 리뷰 대상 커밋에서 검증을 실행한 뒤 코드 분석을 진행합니다.
- 앱 코드·의존성·앱 설정·검증 설정 변경은 루트에서 `yarn lint`, `yarn typecheck`, `yarn test`를 각각 실행합니다. 한 검사가 실패해도 나머지 검사 결과를 확인합니다.
- functions/ 변경은 서버 전용 린트와 타입 체크·테스트를 실행합니다. 빌드를 포함한 명령은 실행하지 않고, 빌드 없는 동등한 검증이 가능한지 확인합니다. 현재 `functions/package.json`의 `npm test`는 빌드를 포함하므로 그대로 실행하지 않습니다.
- 문서만 변경된 경우 실행 검증을 생략할 수 있으며, 생략한 항목과 이유를 보고합니다.
- 실행 도구·의존성·네트워크·권한 부족으로 검증하지 못하면 원인을 명시하고 해당 항목을 '미검증'으로 보고합니다. 실행할 수 없는 환경에서 검증 성공을 추정하지 않습니다.
- PR의 CI 상태를 조회할 수 있으면 최신 리뷰 대상 커밋과 일치하는지 확인합니다. 다른 커밋의 성공 결과를 현재 변경의 검증 근거로 사용하지 않습니다.
- 리뷰 결과에 각 검사의 명령, 대상 커밋, 성공·실패·미검증·생략 상태와 근거를 한국어로 보고합니다. 실패하면 오류 위치와 원인을 확인하고 머지 전 해결 항목으로 명시합니다. 기존 오류는 이번 변경으로 생긴 오류와 구분합니다.
- 검증 실패·미검증 또는 PR CI 실패·진행 중이면 코드상 발견 사항이 없더라도 '전체 검증 통과'나 '머지 가능'이라고 표현하지 않습니다. 코드 분석 결과와 실행 검증 결과를 구분합니다.
- 이 규칙은 리뷰 시 검증 의무를 정하며, Codex의 시스템 상태 문구나 GitHub 머지 제한을 변경하지 않습니다. 머지 차단은 PR CI의 필수 검사와 브랜치 보호 규칙으로 적용합니다.

## 2. 리뷰 작성 기준

- 한국어로 작성하고 실제 동작 오류, 회귀, 데이터 손실, 보안·호환성 문제에 집중합니다.
- 발견 사항마다 우선순위, 파일·줄 위치, 발생 조건, 영향과 코드 근거를 제시합니다.
- 이번 변경이 도입하거나 악화한 문제를 우선합니다. 기존 문제는 변경과의 관계를 설명하고 구분합니다.
- 추측만으로 결함을 단정하지 않습니다. 확인하지 못한 조건이나 실행 결과는 명시합니다.
- 포맷·스타일 등 기계적 검사는 CI에 맡기고, 취향에 따른 리팩터링을 필수 수정으로 제시하지 않습니다.
- 실행하지 않은 테스트를 통과했다고 표현하지 않습니다. 발견 사항이 없더라도 동작 안전성을 보장한다고 표현하지 않습니다.

## 3. EAS Update와 버전 관리

- 이 프로젝트는 RN CLI에 Expo Modules를 연결한 Bare 구조입니다. android/와 ios/를 네이티브 설정 원본으로 보고, prebuild를 자동 실행하거나 전제하지 않습니다.
- 네이티브 코드·의존성·권한·설정 변경이 기존 설치 앱의 런타임과 호환되지 않는 OTA로 발행될 위험을 확인합니다. package.json 변경만으로 새 네이티브 빌드가 필요하다고 단정하지 않습니다.
- 앱 코드와 네이티브 파일이 함께 변경될 때도 OTA가 발행될 수 있는지 워크플로우 이벤트·경로 필터·Job 조건을 함께 확인합니다. 경로 제외만으로 네이티브 변경 차단을 보장한다고 판단하지 않습니다.
- versionCode는 Android 제출용 빌드 번호, runtimeVersion은 OTA 호환성 기준입니다. 둘이 같아야 한다는 EAS 공통 요구사항으로 설명하지 않습니다.
- Android에서는 app.config.js의 versionCode·ANDROID_RUNTIME_VERSION, build.gradle의 versionCode, strings.xml의 expo_runtime_version을 함께 관리하는 프로젝트 규칙을 확인합니다. iOS 런타임은 별도로 판단합니다.
- 버전 검사·증가가 실제 빌드 명령에 연결되어 있는지 확인합니다. 스크립트가 존재한다는 이유만으로 모든 빌드에서 자동 실행된다고 가정하지 않습니다.
- 채널과 업데이트 브랜치를 구분하고, 운영·검증 앱이 같은 채널을 사용할 때 배포 영향 범위를 확인합니다. 서버의 채널 매핑을 로컬 설정만으로 확정하지 않습니다.
- 문서와 코드가 충돌하면 실제 설정·호출 경로를 근거로 불일치를 설명합니다.

## 4. 메시지 동기화와 데이터 일관성

- SQLite 로컬 조회, Firestore 보충·실시간 구독, React Query 캐시 병합 사이에서 메시지가 누락되거나 중복되는 경로를 확인합니다.
- 페이지 크기뿐 아니라 seq 연속성·커서 경계·정렬·메시지 ID 기준 병합을 확인합니다. 최신 구독만으로 미접속 구간 전체가 보충된다고 가정하지 않습니다.
- 서버 전송 성공과 로컬 저장 실패를 구분하고, 재시도가 중복 전송이나 전송 상태 오류를 일으키는지 확인합니다.
- 방 변경·화면 해제 시 구독 정리와 캐시 범위가 올바른지 확인합니다. 의도된 fallback을 결함으로 판단할 때는 실제 불일치나 손실 경로를 제시합니다.

## 5. AI 스트리밍과 오류 처리

- 화면 이탈·요청 변경·연결 오류 시 스트림과 타이머가 정리되고, 이전 응답이 다른 요청이나 화면 상태를 덮어쓰지 않는지 확인합니다.
- 기본 생성과 백업 작업, 재시도 사이의 중복 실행·중복 저장 가능성을 확인합니다.
- 부분 응답·완료·실패 상태와 최종 저장 시점을 확인하고, 클라이언트 연결 종료가 서버 생성 취소까지 보장한다고 가정하지 않습니다.
- Firebase 인증·권한과 비밀값 노출을 확인하고, 로그나 리뷰 댓글에 토큰·개인정보를 그대로 포함하지 않습니다.

## 6. Firebase Functions 서버 코드

functions/ 변경은 서버 진입점과 앱 호출부를 함께 살펴보고, 해당 함수 유형에 필요한 기준을 적용합니다.

### 인증과 접근 권한

- 클라이언트가 전달한 UID·채팅방 ID를 그대로 신뢰하지 않고, 인증된 사용자와 요청 대상의 관계를 확인합니다.
- 기능에 필요한 채팅방 참여 권한·관리자 승인 등을 서버에서 검증하는지 확인합니다.
- Admin SDK는 Security Rules를 우회하므로 서버 코드의 권한 검사를 별도로 확인합니다.
- HTTP·Callable·Task·Firestore 트리거의 호출 주체와 신뢰 경계를 구분합니다. 내부 트리거에 클라이언트 인증 방식을 일괄 요구하지 않습니다.

### 입력 검증과 비용 제어

- 입력 타입·필수값·문자열 길이·이미지 개수와 크기에 적절한 제한이 있는지 확인합니다.
- 외부 URL을 서버에서 가져오는 경우 허용 대상, 내부 주소 접근 위험, 요청 시간 제한과 응답 크기 제한을 확인합니다.
- AI 요청의 중복 실행·무제한 호출·불필요한 재시도로 비용이 증가하는 경로와 호출 제한을 확인합니다.

### 중복 실행과 데이터 일관성

- 이벤트 재전달·Task 재시도·동시 실행 시 DB 저장과 푸시 등 부수 효과가 중복되지 않는지 확인합니다.
- 상태 확인 후 실행하는 것만으로 동시 실행이 차단된다고 판단하지 않습니다. 필요한 경우 트랜잭션·작업 소유권·멱등성 키 등 실제 제어 방식을 확인합니다.
- 기본 AI 생성과 백업 작업의 경합, 결과 덮어쓰기와 부분 실패 이후 복구 경로를 확인합니다.
- 트리거가 감시하는 문서를 수정할 때 반복 실행이 발생하지 않는지 확인합니다.

### 오류와 운영 설정

- 비동기 작업을 적절히 await·반환하고, 응답 종료 뒤 완료가 필요한 작업을 방치하지 않는지 확인합니다.
- 외부 API 시간 제한, 함수 제한 시간과 재시도 설정을 함께 확인합니다. 주석보다 실제 설정과 동작을 기준으로 판단합니다.
- 일시적 오류와 영구적 오류를 구분하고, 오류를 숨긴 채 성공으로 처리하거나 무의미한 재시도를 반복하는 경로를 확인합니다.
- 비밀값은 서버 Secret 등 적절한 보관 방식으로 관리하고, 로그·응답에 토큰이나 민감한 대화 내용을 노출하지 않습니다.

### 검증과 배포

- functions/package.json의 서버 전용 검증 명령과 CI 호출 여부를 확인합니다. 앱 CI 통과만으로 서버 코드까지 검증됐다고 판단하지 않습니다.
- 빌드를 포함한 명령은 사용자 요청 없이 실행하지 않습니다. 실행하지 못한 검증과 필요한 후속 검증을 명시합니다.
- Functions 변경은 EAS Update로 배포되지 않습니다. 서버 배포 필요 여부, 앱과 서버의 배포 순서 및 구버전 앱의 요청·응답 호환성을 확인합니다.
