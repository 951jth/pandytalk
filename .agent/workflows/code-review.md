# 코드 리뷰 규칙

## 1. 적용 범위와 작업 경계

- 로컬 변경사항 및 GitHub PR 리뷰에 적용합니다. 루트와 변경 파일에 적용되는 하위 AGENTS.md도 함께 읽습니다.
- 변경 diff를 중심으로 호출부·데이터 흐름·설정 등 판단에 필요한 관련 코드를 확인합니다.
- 리뷰 요청에서는 파일 수정·커밋·push·머지·EAS Update·빌드·스토어 제출을 수행하지 않습니다.
- GitHub PR 리뷰 의견 작성은 허용합니다. 수정 요청은 별도 작업으로 처리하고 기존 승인 규칙을 따릅니다.
- 명시적으로 요청하지 않은 빌드, 전체 테스트·lint는 실행하지 않습니다. 필요한 검증과 실제 실행 여부를 구분해 보고합니다.

## 2. 리뷰 작성 기준

- 한국어로 작성하고 실제 동작 오류, 회귀, 데이터 손실, 보안·호환성 문제에 집중합니다.
- 발견 사항마다 우선순위, 파일·줄 위치, 발생 조건, 영향과 코드 근거를 제시합니다.
- 이번 변경이 도입하거나 악화한 문제를 우선합니다. 기존 문제는 변경과의 관계를 설명하고 구분합니다.
- 추측만으로 결함을 단정하지 않습니다. 확인하지 못한 조건이나 실행 결과는 명시합니다.
- 포맷·스타일 등 기계적 검사는 CI에 맡기고, 취향에 따른 리팩터링을 필수 수정으로 제시하지 않습니다.
- 실행하지 않은 테스트를 통과했다고 표현하지 않습니다. 발견 사항이 없더라도 동작 안전성을 보장한다고 표현하지 않습니다.

## 3. EAS Update와 버전 관리

- 이 프로젝트는 RN CLI에 Expo Modules를 연결한 Bare 구조입니다. android/와 ios/를 네이티브 설정 원본으로 보고, prebuild를 자동 실행하거나 전제하지 않습니다.
- 네이티브 코드·의존성·권한·설정 변경이 기존 설치 앱의 런타임과 호환되지 않는 OTA로 발행될 위험을 확인합니다. package.json 변경만으로 새 네이티브 빌드가 필요하다고 단정하지 않습니다.
- 앱 코드와 네이티브 파일이 함께 변경될 때도 OTA가 발행될 수 있는지 워크플로우 이벤트·경로 필터·Job 조건을 함께 확인합니다. 경로 제외만으로 네이티브 변경 차단을 보장한다고 판단하지 않습니다.
- versionCode는 Android 제출용 빌드 번호, runtimeVersion은 OTA 호환성 기준입니다. 둘이 같아야 한다는 EAS 공통 요구사항으로 설명하지 않습니다.
- Android에서는 app.config.js의 versionCode·ANDROID_RUNTIME_VERSION, build.gradle의 versionCode, strings.xml의 expo_runtime_version을 함께 관리하는 프로젝트 규칙을 확인합니다. iOS 런타임은 별도로 판단합니다.
- 버전 검사·증가가 실제 빌드 명령에 연결되어 있는지 확인합니다. 스크립트가 존재한다는 이유만으로 모든 빌드에서 자동 실행된다고 가정하지 않습니다.
- 채널과 업데이트 브랜치를 구분하고, 운영·검증 앱이 같은 채널을 사용할 때 배포 영향 범위를 확인합니다. 서버의 채널 매핑을 로컬 설정만으로 확정하지 않습니다.
- 문서와 코드가 충돌하면 실제 설정·호출 경로를 근거로 불일치를 설명합니다.

## 4. 메시지 동기화와 데이터 일관성

- SQLite 로컬 조회, Firestore 보충·실시간 구독, React Query 캐시 병합 사이에서 메시지가 누락되거나 중복되는 경로를 확인합니다.
- 페이지 크기뿐 아니라 seq 연속성·커서 경계·정렬·메시지 ID 기준 병합을 확인합니다. 최신 구독만으로 미접속 구간 전체가 보충된다고 가정하지 않습니다.
- 서버 전송 성공과 로컬 저장 실패를 구분하고, 재시도가 중복 전송이나 전송 상태 오류를 일으키는지 확인합니다.
- 방 변경·화면 해제 시 구독 정리와 캐시 범위가 올바른지 확인합니다. 의도된 fallback을 결함으로 판단할 때는 실제 불일치나 손실 경로를 제시합니다.

## 5. AI 스트리밍과 오류 처리

- 화면 이탈·요청 변경·연결 오류 시 스트림과 타이머가 정리되고, 이전 응답이 다른 요청이나 화면 상태를 덮어쓰지 않는지 확인합니다.
- 기본 생성과 백업 작업, 재시도 사이의 중복 실행·중복 저장 가능성을 확인합니다.
- 부분 응답·완료·실패 상태와 최종 저장 시점을 확인하고, 클라이언트 연결 종료가 서버 생성 취소까지 보장한다고 가정하지 않습니다.
- Firebase 인증·권한과 비밀값 노출을 확인하고, 로그나 리뷰 댓글에 토큰·개인정보를 그대로 포함하지 않습니다.
