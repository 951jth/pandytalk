# Firebase Cloud Functions 작성·리뷰 규칙

functions/ 코드·설정·의존성 작성 및 리뷰에 적용합니다. 서버 진입점과 앱 호출 계약을 함께 확인합니다. 리뷰 결과 작성과 실행 경계는 [code-review.md](code-review.md)를 따릅니다.

## 서버 점검 기준

functions/ 변경은 서버 진입점과 앱 호출부를 함께 살펴보고, 해당 함수 유형에 필요한 기준을 적용합니다.

### 아키텍처 및 최적화

- **관심사 분리:** 트리거 핸들러 코드와 순수 비즈니스 로직(Service/Core)이 분리되어 있어, 단위 테스트가 용이한 구조인지 확인합니다.
- **성능 및 콜드 스타트:** V2(2세대) 사용 시 `concurrency` 설정이 적절한지 점검하고, 전역(Global) 스코프를 활용해 DB 커넥션 등 외부 리소스를 재사용하여 콜드 스타트를 최소화하는지 확인합니다.

### 인증과 접근 권한

- 클라이언트가 전달한 UID·채팅방 ID를 그대로 신뢰하지 않고, 인증된 사용자와 요청 대상의 관계를 확인합니다.
- 기능에 필요한 채팅방 참여 권한·관리자 승인 등을 서버에서 검증하는지 확인합니다.
- Admin SDK는 Security Rules를 우회하므로 서버 코드의 권한 검사를 별도로 확인합니다.
- HTTP·Callable·Task·Firestore 트리거의 호출 주체와 신뢰 경계를 구분합니다. 내부 트리거에 클라이언트 인증 방식을 일괄 요구하지 않습니다.

### 입력 검증과 비용 제어

- 입력 타입·필수값·문자열 길이·이미지 개수와 크기에 적절한 제한이 있는지 확인합니다.
- 외부 URL을 서버에서 가져오는 경우 허용 대상, 내부 주소 접근 위험, 요청 시간 제한과 응답 크기 제한을 확인합니다.
- AI 요청의 중복 실행·무제한 호출·불필요한 재시도로 비용이 증가하는 경로와 호출 제한을 확인합니다.

### 중복 실행과 데이터 일관성

- 이벤트 재전달·Task 재시도·동시 실행 시 DB 저장과 푸시 등 부수 효과가 중복되지 않는지 확인합니다.
- 상태 확인 후 실행하는 것만으로 동시 실행이 차단된다고 판단하지 않습니다. 필요한 경우 트랜잭션·작업 소유권·멱등성 키 등 실제 제어 방식을 확인합니다.
- 기본 AI 생성과 백업 작업의 경합, 결과 덮어쓰기와 부분 실패 이후 복구 경로를 확인합니다.
- **무한 루프 방지:** Firestore `onDocumentUpdated` 등의 트리거에서 불필요한 재귀 호출을 막기 위해, 반드시 `change.before`와 `change.after`를 비교하여 특정 필드가 변경되었을 때만 후속 로직이 실행되는지 엄격히 확인합니다.

### 오류와 운영 설정

- 비동기 처리 누락(dangling promise) 및 의미 없는 에러 삼키기(swallowing)를 엄격히 금지합니다.
- 외부 API 시간 제한, 함수 제한 시간과 재시도 설정을 함께 확인합니다. 주석보다 실제 설정과 동작을 기준으로 판단합니다.
- 일시적 오류와 영구적 오류를 구분하여 무의미한 재시도를 방지합니다.
- **보안 및 환경 변수:** 하드코딩된 API 키를 금지하고, Firebase의 내장 파라미터(`defineSecret`, `defineString`)를 사용하여 안전하게 환경 변수를 주입받는지 확인합니다. 로그나 응답에 민감한 데이터가 노출되지 않도록 주의합니다.

### 검증과 배포

- functions/package.json의 서버 전용 검증 명령과 CI 호출 여부를 확인합니다. 앱 CI 통과만으로 서버 코드까지 검증됐다고 판단하지 않습니다.
- 빌드를 포함한 명령은 사용자 요청 없이 실행하지 않습니다. 실행하지 못한 검증과 필요한 후속 검증을 명시합니다.
- Functions 변경은 EAS Update로 배포되지 않습니다. 서버 배포 필요 여부, 앱과 서버의 배포 순서 및 구버전 앱의 요청·응답 호환성을 확인합니다.

### 서버 검증 실행

- 서버 리뷰 시 `functions/` 디렉터리에서 `npm run lint`와 빌드 없는 타입 체크(`npx tsc --noEmit`)를 기본으로 실행합니다.
- 시간이 오래 걸리거나 에뮬레이터 환경이 필요한 서버 테스트(`npm test`)는 핵심 비즈니스 로직이나 테스트 코드가 변경되었을 때만 제한적으로 실행합니다.
- 검증을 위해 소스를 임의로 고치거나 빌드·서버 배포·실제 외부 API 호출로 우회하지 않습니다.
