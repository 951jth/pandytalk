# 🚀 서버리스 백엔드 플랫폼 비교 가이드

## 1. 플랫폼 한눈에 비교

| 특징 | Firebase (Google) | Supabase (Open Source) | AWS Serverless (Amplify/Lambda) |
| :--- | :--- | :--- | :--- |
| **데이터베이스** | NoSQL (Firestore) | **Relational (PostgreSQL)** | NoSQL (DynamoDB) / RDS |
| **주요 강점** | 모바일 앱 생태계 (SDK) | SQL의 강력함, 개방성 | 무한한 확장성, 생태계 |
| **학습 곡선** | 매우 낮음 (쉬움) | 낮음 (SQL 지식 필요) | 매우 높음 (어려움) |
| **실시간 기능** | 기본 제공 (강력함) | 기본 제공 (성숙도 상승 중) | AppSync(GraphQL)로 제공 |
| **가격 정책** | 사용량 기반 (무료 티어 넉넉) | 인스턴스/사용량 기반 | 매우 복잡하지만 가장 저렴할 수 있음 |

---

## 2. 플랫폼별 상세 분석

### 🔥 Firebase
> "모바일 앱 개발을 위한 최고의 올인원 패키지"

*   **장점**:
    *   **강력한 모바일 SDK**: Android, iOS 개발 시 Crashlytics, Analytics, Remote Config 등 앱 운영에 필수적인 도구들이 완벽하게 통합되어 있습니다.
    *   **검증된 실시간성**: Firestore의 리얼타임 리스너는 채팅 앱 구현에 있어 가장 안정적입니다.
    *   **구현 속도**: 인증(Auth), 파일 저장소(Storage), 알림(FCM)을 설정하는 데 몇 분이면 충분합니다.
*   **단점**:
    *   **NoSQL의 한계**: 복잡한 관계형 데이터(JOIN 등)를 처리하기 어렵고, 데이터 구조 변경 시 마이그레이션이 까다롭습니다.
    *   **Vendor Lock-in**: 구글 서비스에 완전히 종속되어 다른 플랫폼으로 옮기기 매우 어렵습니다.
    *   **비용 예측**: 특정 쿼리나 데이터 구조가 잘못되면 비용이 급격히 늘어날 수 있습니다.

### ⚡ Supabase
> "PostgreSQL의 힘을 서버리스로 제공하는 오픈소스 Firebase 대안"

*   **장점**:
    *   **진짜 SQL (PostgreSQL)**: 관계형 데이터베이스를 그대로 사용하므로 데이터 정규화 및 복잡한 쿼리가 가능합니다.
    *   **개방성**: 오픈소스 기반이므로 필요하면 자체 서버(Self-hosting)에 구축하여 종속성을 탈피할 수 있습니다.
    *   **Edge Functions**: Deno 기반의 엣지 함수로 지연 시간이 매우 짧은 서버 로직을 실행할 수 있습니다.
*   **단점**:
    *   **모바일 생태계 미흡**: Firebase의 Crashlytics나 Analytics 같은 모바일 운영 도구가 없어 별도의 3rd party 서비스를 써야 합니다.
    *   **진입 장벽**: NoSQL에 비해 DB 스키마 설계 및 SQL 지식이 필요합니다.

### ☁️ AWS Serverless (Amplify / Lambda)
> "전 세계에서 가장 거대하고 정교한 클라우드 인프라"

*   **장점**:
    *   **압도적 확장성**: 전 세계 규모의 서비스를 운영하기에 가장 적합하며, 수천 가지의 AWS 서비스와 연동할 수 있습니다.
    *   **세밀한 제어**: 보안(IAM), 네트워크 설정 등을 아주 미세하게 조정할 수 있습니다.
*   **단점**:
    *   **극악의 난이도**: 설정해야 할 것이 너무 많고, 용어 자체가 어렵습니다. (Amplify가 이를 보완하려 하지만 여전히 복잡함)
    *   **관리 오버헤드**: 단순한 기능을 하나 만들더라도 권한 설정 등에 많은 시간이 소요됩니다.

## 3. 팬디톡 프로젝트를 위한 제언

*   **현재 상태 유지 (Firebase)**: 
    현재 프로젝트처럼 **빠른 출시, 모바일 운영 도구(Crashlytics/Analytics)의 중요성, 채팅 기능의 실시간성**이 최우선이라면 Firebase가 정답입니다.
*   **Supabase 고려 시점**: 
    데이터 간의 관계가 매우 복잡해져서 SQL의 JOIN 기능이 절실하거나, 특정 기업의 종속성에서 벗어나고 싶을 때 고려하세요.
*   **AWS 고려 시점**: 
    수백만 명 이상의 유저를 수용해야 하거나, 이미 기업 인프라가 AWS로 구축되어 통합이 필요할 때 고려하세요.
