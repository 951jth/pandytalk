## 면접용 한 줄 요약

AI 응답 지연의 대부분은 OpenAI 첫 토큰 대기에서 발생했고, 클라이언트의 SSE 수신/버퍼링/렌더링 비용은 매우 작았습니다. 따라서 UX 개선의 핵심은 전체 응답 완료를 기다리지 않고 첫 토큰부터 스트리밍으로 보여주며, Firestore 저장은 후처리로 분리한 점입니다.

## 순수 스트리밍 vs 일반 응답 공정 비교

`testAiStreamBenchmark`에서 tool-call/preflight를 제외하고, 같은 프롬프트를 `stream:true`와 `stream:false`로 직접 호출해 비교했습니다.

| 측정 항목 | 결과 |
| :--- | ---: |
| 반복 횟수 | 6회 |
| 스트리밍 첫 응답 평균 | 771.17ms |
| 일반 응답 완료 평균 | 2,511.84ms |
| 첫 응답 체감 개선 | 1,740.67ms |
| 개선율 | 69.30% |

| 테스트 로그 | 반복 | 스트리밍 첫 응답 평균 | 일반 응답 완료 평균 | 첫 응답 체감 개선 | 개선율 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 1차 | 3회 | 758.33ms | 2,271ms | 1,512.67ms | 66.61% |
| 2차 | 3회 | 784ms | 2,752.67ms | 1,968.67ms | 71.52% |

| 항목 | 일반 (Non-Streaming) | SSE (Streaming) | 개선 효과 |
| :--- | ---: | ---: | :--- |
| 사용자 첫 응답 체감 시간 | 2,511.84ms | 771.17ms | 약 69.30% 감소 |

측정 기준:

- 일반 응답은 `stream:false` 요청이 완료되어 전체 응답을 받을 수 있는 시점을 기준으로 측정했습니다.
- SSE 응답은 `stream:true` 요청에서 첫 content chunk를 받은 시점을 기준으로 측정했습니다.
- 비교 목적은 전체 생성 완료 시간이 아니라, 사용자가 답변이 시작됐다고 체감하는 첫 응답 시간을 비교하는 것입니다.
- tool-call/search/preflight 로직은 제외하고, 같은 모델과 같은 프롬프트를 대상으로 stream 옵션만 다르게 측정했습니다.
- 응답이 짧으면 시간이 과도하게 낮게 보일 수 있으므로, 벤치마크 결과는 평균 응답 문자 수와 함께 확인합니다. 장문 답변 비교에서는 일반/SSE 응답 모두 1,000자 내외 이상인지 먼저 검증합니다.

> 같은 조건에서 스트리밍은 일반 응답처럼 전체 생성 완료를 기다리지 않고 첫 청크를 받을 수 있어, 첫 응답 체감 시간이 평균 1.74초(69.30%) 빨랐습니다.
