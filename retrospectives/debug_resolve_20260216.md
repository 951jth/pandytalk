# 🚀 대용량 채팅 데이터 최적화: 실시간 구독 부하 방지 및 데이터 간극(Gap) 자동 복구 전략

> **Project:** CSHCHATAPP (Side Project)  
> **Topic:** 실시간 구독(onSnapshot) 부하 방어 및 하이브리드 저장소 간 데이터 정합성 최적화
> **Tech Stack:** React Native, Firestore, SQLite, React Query, TypeScript

## 1. 배경 및 문제 상황 (Background & Problem)

기본적인 데이터 동기화 구조에서 대용량 채팅방 진입 시 다음과 같은 성능 병목 및 비용 이슈 발생 위험 확인.

- **구독 부하 (Massive Subscription Load):** 사용자가 오랜만에 접속했을 때, 로컬 DB와 서버 사이의 큰 간극(예: 수천 개)을 `onSnapshot`이 한꺼번에 가져오려고 시도함에 따른 메모리 과부하 및 앱 프리징(Freezing).
- **데이터 유실 (Data Gaps):** 부분적인 네트워크 장애나 비정상 종료로 인해 로컬 DB의 시퀀스(`seq`)가 불연속적으로 저장될 경우, 일반적인 페이징 로직으로는 중간에 뻥 뚫린 데이터를 감지하거나 채울 수 없음.
- **불필요한 리드 비용:** 채팅방에 진입할 때마다 상태를 동기화하기 위해 중복된 Firestore 읽기 요청 발생.

## 2. 해결 과정 (Problem Solving Process)

### 이슈 1: 구독과 페이징의 역할 분리 (Decoupling)

**A. 해결책**
실시간 리스너(`onSnapshot`)는 오직 **"입장 시점 이후"**의 새 메시지만 감시하도록 역할을 제한하고, 과거 데이터는 사용자 조작(스크롤)에 따라 가져오도록 설계 변경.

**B. 상세 구현**

- `useSubscribeChatMessages`: 부모로부터 전달받은 `serverLastSeq`를 기준으로 구독 시작. 입장 시점 이전의 메시지는 물리적으로 무시하여 부하 원천 차단.
- `useChatMessagesInfinite`: 인피니트 쿼리의 시작점을 로컬 DB가 아닌 '서버 최신 시퀀스'로 고정하여 데이터의 상단(최신)부터 채워나감.

---

### 이슈 2: 지능형 간극(Gap) 감지 및 자동 복구

**A. 해결책**
로컬 DB 조회 결과와 서버 커서 간의 **시퀀스 연속성**을 체크하는 로직을 페이징 엔진에 주입.

**B. 상세 구현**

- `hasGap` 감지 로직: `(localMessages[0]?.seq || 0) < cursor - 1` 조건문 도입.
- **작동 원리:** SQLite에서 데이터를 가져왔는데, 기대했던 번호(커서 - 1)보다 낮은 번호가 발견되면 중간 데이터가 비어있다고 판단하고 즉시 Firestore에서 해당 구간을 보충 조회(Paging Get).

---

### 이슈 3: 성능 및 비용 조율 (Performance Orchestration)

**A. 해결책**
`useChatMessageList`를 중앙 허브로 사용하여 공유 데이터(`roomInfo`)를 하위 훅들에게 전파하여 중복 조회를 최소화.

**B. 최적화 내용**

- **Freshness 보장:** `useChatRoomInfo`의 `staleTime`을 `0`으로 설정하여 입장 시마다 서버의 최신 끝점(`lastSeq`)을 백그라운드에서 즉시 재확인.
- **Inverted List 대응:** `FlashList`의 `inverted` 속성에 따른 인덱스 반전(`DESC` 정렬)을 고려하여 `localMessages[0]`이 간극 체크의 시작점임을 명확히 정의함.
