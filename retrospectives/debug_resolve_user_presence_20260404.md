# 🚀 debug_resolve: 유저 접속 상태(Presence) 신뢰성 및 비용 최적화 (2026-04-04)

## 📌 개요
사용자의 실시간 온라인/오프라인 상태를 시각적으로 제공하여 서비스의 활성도를 높이고, 데이터 로딩 시 사용자 경험(UX)을 개선하기 위해 전역 스켈레톤 UI 시스템을 도입했습니다. 또한, 서버 비용 최적화를 위해 실시간 상태 관리와 배치 클린업 로직을 병행 적용했습니다.

## ✨ 주요 변경 사항
### 1. 실시간 접속 상태(Presence) 시스템
- **`useUserPresence` 훅**: 앱의 `AppState`를 감시하여 포그라운드 진입 시 `online`, 백그라운드/종료 시 `offline` 상태를 Firestore에 동기화합니다.
- **`userService.updateLastSeen`**: 마지막 활동 시간(`lastSeen`)과 접속 상태(`status`)를 원자적으로 업데이트하도록 개선했습니다.
- **`OnlineBadge`**: 아바타 우측 하단에 상태를 표시하는 공통 UI 컴포넌트를 설계하여 일관된 시각적 피드백을 제공합니다.

### 2. 전역 스켈레톤 UI 시스템
- **`Skeleton` 베이스**: `Animated` 라이브러리를 활용하여 부드러운 펄스 효과가 적용된 공통 스켈레톤 조각을 구현했습니다.
- **레이아웃 스켈레톤**: `UserListSkeleton`, `ChatListSkeleton`, `UserManageSkeleton` 등 각 화면의 실제 카드 레이아웃과 1:1로 매칭되는 전용 스켈레톤을 제작하여 로딩 시 레이아웃 시프트를 방지했습니다.

### 3. 서버 비용 및 성능 최적화
- **가상 오프라인(Virtual Offline)**: 클라이언트 단에서 `status === 'online'`이더라도 `lastSeen`이 15분 이상 경과했다면 오프라인으로 간주하는 로직을 추가하여 서버 업데이트 빈도를 줄였습니다.
- **`cleanupInactiveUsers` 스케줄러**: 30분 주기로 실행되며 1시간 이상 활동 없는 유저를 정리하는 클라우드 펑션 배치를 도입하여 데이터 정합성을 확보했습니다.

### 4. 컴포넌트 리네이밍 및 리팩토링
- 역할을 명확히 하기 위해 `ChatMember`를 `UserListItem`으로, 기존 `UserListItem`을 `UserManageItem`으로 리네이밍하고 관련 경로를 모두 업데이트했습니다.

## 🛠️ 기술적 의의
- **UX 향상**: 로딩 스피너 대신 스켈레톤을 사용하여 앱의 반응성을 높이고, 실시간 상태 표시로 커뮤니티성을 강화했습니다.
- **비용 최적화**: Firestore의 읽기/쓰기 비용을 고려하여 클라이언트 중심의 상태 판단 로직과 서버 배치를 적절히 조합한 하이브리드 아키텍처를 설계했습니다.
- **유지보수성**: 유저 목록 관련 컴포넌트들을 역할별로 재정의하여 향후 관리자 기능 확장에 유연하게 대응할 수 있는 기반을 마련했습니다.
