# 🚀 Bug Fix: 채팅 메시지 동기화 및 누락 오류 해결 (2026-03-28)

## 📌 개요

사용자가 푸쉬 알림을 통해 채팅방에 진입하거나, 네트워크 상태에 따라 중간 메시지가 유실(Gap)되었을 때 데이터가 자동으로 복구되지 않던 치명적인 오류를 수정하였습니다.

## ✨ 주요 변경 사항

### 1. 데이터 연속성 검증 로직 도입 (Gap Detection)

- **hasGapInRange**: 로컬 DB에서 조회된 메시지들 사이의 시퀀스(`seq`) 번호가 연속적인지 확인합니다. (예: `105`번 다음이 `100`번인 경우 중간이 빈 것으로 판단)
- **hasCursorGap**: 조회를 시작하려는 위치(`cursorSeq`)와 실제 DB에서 반환된 첫 데이터 사이에 간극이 있는지도 함께 체크합니다.
- 위 조건 중 하나라도 충족되면 로컬 데이터를 믿지 않고 **서버에서 즉시 새로운 데이터를 가져와 동기화**하도록 개선했습니다.

### 2. 첫 페이지 조회 시 Stale 여부 판단 강화

- 기존에는 `isLocalStale` 판정이 단순하여, 로컬에 최신 번호가 하나라도 박혀 있으면 아래쪽에 구멍이 뚫려 있어도 서버 조회를 하지 않던 문제를 해결했습니다.
- 이제 첫 페이지 진입 시에도 데이터의 완전성(Integrity)을 검증하여 완벽한 목록을 보장합니다.

### 3. 개발용 상세 디버그 트레이싱 로그 추가

- `__DEV__` 환경에서 서버 조회가 발생하는 구체적인 **[이유]**와 **[로컬/서버 데이터 범위]**를 실시간으로 출력합니다.
- 이를 통해 추후 발생할 수 있는 동기화 문제를 육안으로 즉시 추적할 수 있는 환경을 마련했습니다.

### 4. EAS Update 런타임 버전 고정

- [app.json](cci:7://file:///c:/Users/CSH/Projects/pandytalk/app.json:0:0-0:0)의 `runtimeVersion`을 `"1.2.3"`으로 명시적으로 고정하여, `policy: appVersion` 사용 시 발생하던 빌드 에러를 해결하고 구글 플레이 버전과의 정합성을 확보했습니다.

## 🛠️ 기술적 의의

- **Local-First 동기화 안정화**: SQLite와 Firestore 간의 데이터 정합성을 보장하는 강력한 Fallback 메커니즘을 구축했습니다.
- **성능과 정확도의 균형**: 매번 서버에서 데이터를 가져오지 않으면서도, 데이터가 불완전할 때만 선택적으로 서버를 호출하여 리소스를 아꼈습니다.
- **디버깅 편의성**: 추적하기 어려운 '데이터 유실' 현상을 로그로 구조화하여 유지보수성을 높였습니다.
